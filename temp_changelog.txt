## [3 February 2026 - 22:30] - Critical Bug Fix: operator>> Infinite Recursion + EK Constructor Bias

### 🔴 CRITICAL BUGFIX: Right shift operator caused infinite loop, EK constructor missing bias

**Problem 1: Infinite recursion in operator>>**
- Missing \operator>>(int shift) const\ overload caused template version to call itself
- Stack overflow on any right shift operation
- test_priority7_shift hung at test 9 (right shift tests)

**Problem 2: EK constructor didn't add bias**
- \int128_ek_t{10}\ stored 10 instead of 10 + K (K = 2^126)
- All EK values were incorrect (missing bias offset)
- Broke arithmetic, comparisons, and to_string()

**Problem 3: EK operator-- used binary decrement**
- \--data[0]\ decrements stored value, not semantic value
- Changed to \*this -= int128_param_t{1}\ for correct bias handling

**Solutions:**
1. Added \operator>>(int shift) const\ following same pattern as \operator<<\`n2. Enhanced constructor to add bias for excess_k representation
3. Fixed operator-- to delegate to operator-= for EK

**Tests fixed:**
- test_priority7_shift.cpp: **28/28 passing** ✅ (was: hung)
- test_native_arithmetic.cpp: **47/47 passing** ✅ (was: 33/47)
